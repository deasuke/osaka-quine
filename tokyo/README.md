# 山手線バージョン

山手線で作り直したものです。

## 使い方
使用法は本家と同じ。フォントが綺麗になった分、大きくなっています。
```bash
% ruby tokyo.rb | ruby | ruby ...
```
とすると順に内回り
```bash
% ruby tokyo.rb x | ruby - x | ruby - x ...
```
とすると順に外回り

## 高輪ゲートウェイ追加版

[高輪ゲートウェイ駅](https://www.jreast.co.jp/estation/station/info.aspx?StationCd=1750)（2020年3月14日開業）を品川〜田町間に追加し、30駅に更新しました。
引数なし・ありの両方向で、30回実行すると元のソースにバイト単位で一致します。
生成済みの `tokyo.rb` だけで動き、Ruby標準添付の `zlib` を使います。

### 長い駅名の扱い

「高輪ゲートウェイ」は省略せず、既存駅と同じ28×56桁の文字を8文字縦に並べます。
アートの横幅は従来の76桁のままです。新駅のソースは329行になります。
2文字駅のソースは101行で、余白を増やして追加のフォントと処理を収めています。

元の54字の圧縮データはそのまま利用します。「高」は既存データにあるので、新しい字形は「輪ゲートウェイ」の7字だけです。
`new-glyphs.json` に28×28のビットマップ（`#`が駅名の画素、`.`が背景）として保存し、生成時にzlibとBase64で埋め込みます。
新しい7字には既存の駅名符号で使っていない `YZ[]^_` とバッククォートを割り当て、バッククォートも駅名の終端として扱います。
逆方向の回転数は28回から29回に変更しました。

駅名リストが長くなったため、ソース先頭のリストも `%w{…}*""` で折り返し可能にしました。
また、自己出力部分の閉じ記号や式の途中に改行が入らないようにします。
位置調整には空白ではなくセミコロンを挿入し、再実行時に `.squeeze(';')` で連続するセミコロンを1個に戻します。
そのため、コードに空白の塊ができて駅名に紛れ込むことも、巡回ごとに調整用の文字が蓄積することもありません。
元の圧縮フォントには連続したセミコロンがないことも検証しています。

### 再生成と検証

```sh
cd tokyo
sh tokyo.sh
```

生成、構文確認、30駅の内回り・外回り一周、逆操作、76桁幅、新しい7字の表示を検証します。全駅の表示全体について、字形の画素以外に空白がないことも確認します。
`tokyo-maker.rb` と `new-glyphs.json` が再生成に必要です。生成済みソースの実行時には不要です。

新駅から始まる実行可能なサンプルは [examples/takanawa-gateway.rb](examples/takanawa-gateway.rb) にあります。
東京から外回りに5駅進んでも同じ表示を得られます。

```sh
ruby tokyo.rb x | ruby - x | ruby - x | ruby - x | ruby - x
```

追加字形はmacOSのヒラギノ角ゴシックを28pxでラスタライズしたものです。線が密集する「輪」はW2、それ以外はW6を使用します。「ー」は縦書きに合わせて90度回転します。
ビットマップを編集する場合はJSONを直接変更できます。元の字形を再取得する場合のみ、macOSで次を実行します。

```sh
swift tools/render-new-glyphs.swift > new-glyphs.json
```

## 2017年版：大阪の反省を生かした点や違いなど

1. 駅名ループの使用文字
大阪環状線の駅名の使用文字は35種類だが、山手線の駅名の使用文字は54種類。従ってそのまま駅名の最後にくるものと来ないものの区別を付けると108種となり、表示可能文字の個数を越えてしまう。そこで、駅名の最後に来る文字は22種であることを利用し、駅名の最後は`e-z`を、最後以外は`#-X`を利用した。前者を54で割った余りは0〜14または47〜53となるので駅名の最後にくる可能性のある文字はこの範囲に来るように配置した。 例えば「田」の場合、駅名の最後に来る場合は`n`となり、最後以外の場合は`8`となる。何れにしてもASCIIコードを54で割ると余りが2となり、インデックス2を利用してフォント情報を参照する。

2. 圧縮率最大の配置を検索
先の条件を満す漢字の配置は無数にあるので、絨毯爆撃(大域的な乱数順列)と局所探索(局所的な乱数順列)を組合せて圧縮率が最大となる配置を探索した。無作為のものと比較して200ビットくらいは小さくなった。

3. 90進数を利用
91進数を利用するのはやめて`{|}`を利用しない90進数を用いた。使用範囲は本家の`!-[`と`]-z`に加えて`~`の90文字である。文字のASCIIコードを`i`とするとき、`i%124%90`とするだけでこれらの文字が巧く`0-89`の範囲に治まる。`~`が丁度`\`の場所を埋めてくれるのである。

4. 本家で用いていたテクニックの採用
メソッドの最後で自分自身を返すことにより、`g[][][][]`のような形でメソッド`g`を何度も呼べる。また、`g[][][something]`の方が`g[][][];something`より1文字短いので`->`を`proc`にすることで引数の個数を可変とした。しかし`g[][][something]`は2度しか登場していないのでタイである。

5. 最悪条件の駅から調整
隙間となる空白部分の多い漢字の2文字の駅が最悪である。調査をすると巣鴨がそれに当るので、巣鴨を中心に調整したので、調整は楽に済んだ。
